Important timing detail: the line and parent each have their own viewport trigger. The 300ms and 400ms delays are relative to those separate triggers, not necessarily one shared clock. If both become visible in the same scroll event, the line begins roughly 100ms later. Slow scrolling, the parent’s movement, or a different layout can change their relative trigger times.

Why it feels like multiple beats

The rise and fade do not progress identically. At halfway through the 1000ms motion, outExpo has completed 96.875% of the movement: only 1.5625px of the original 50px remains. Opacity is only 0.5. The element settles into position early while becoming fully visible more slowly. That separation makes the movement feel controlled rather than like a rigid object moving and fading at the same rate.

The line’s width changes the horizontal position of the label because they are adjacent items in a flex row. As the line grows 0 → 50px, “Upscale” is pushed approximately 50px to the right. The label therefore appears to have its own later movement even though it has no separate transform animation.

Scrolling also reveals children at different physical positions. A scissors image near the top and headline below it enter your field of view at different times. Images are marked loading="lazy", so their load/render timing can add another apparent reveal. That is not evidence of a separate fade timeline.

Runtime evidence: before entrance, the parent had opacity 0 and a 50px translation. During the reveal, a sample showed parent opacity 0.3865 and translation 3.4315px. The label, scissors, and headline still had their own computed opacity 1 and transform none. A child’s computed opacity does not include its parent’s opacity; the parent fades the complete rendered subtree.

Trigger semantics

All homepage scroll entrances use SCROLL_INTO_VIEW, offset 0%, loop false, and play-in-reverse false. The runtime compares the element’s bounding rectangle with the viewport. There is no “wait until the element reaches 80% of the screen” offset here. The initial transform is included in that bounding rectangle. Once triggered, the animation continues with elapsed time even if you stop scrolling. It is not a scrubbed scroll-progress animation. Returning to the section does not replay it during the same normal page session; reload or interaction reinitialization can reset it.

The entrance is compounded, not staggered card by card

How to recreate the quality, and improve it

A small motion vocabulary

Recreate these primitives: one-shot fade/rise, independent line growth, scale/rotate-then-extend ornaments, coordinated card text/overlay/frame hover, color transitions, and sliding panels. The craft comes from choosing which element groups own each primitive, spacing them well, and overlapping their timings. You do not need a different effect for every visible element.

outExpo(p) = p === 1 ? 1 : 1 − 2^(−10p); outCubic(p) = 1 − (1 − p)^3; outQuad(p) = 1 − (1 − p)^2; inQuad(p) = p²; inOutQuad(p) = 2p² for p < .5, otherwise 1 − (−2p + 2)² / 2. CSS ease and ease-out are different cubic curves; an empty IX2 easing string resolves to linear progress. Webflow’s exact mathematical outExpo is not identical to an arbitrary CSS ease-out curve.

Dependency-free reveal example

This teaching example matches the main parent fade/rise channels and gold-line growth, using your own data-reveal and data-title-line elements. IntersectionObserver is a practical replacement for Webflow’s viewport test, not a byte-for-byte recreation of its scroll event engine. It gives each target its own trigger and plays once. Its initial-state setup assumes dedicated motion wrappers without pre-existing transforms.

const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
const clamp = p => Math.max(0, Math.min(1, p));
const expoOut = p => p === 1 ? 1 : 1 - 2 ** (-10 * p);
const quadInOut = p => p < .5 ? 2*p*p : 1 - (-2*p+2)**2/2;

function tween(delay, duration, update) {
  const start = performance.now() + delay;
  function frame(now) {
    const p = clamp((now - start) / duration);
    update(p);
    if (p < 1) requestAnimationFrame(frame);
  }
  requestAnimationFrame(frame);
}

if (!reduce) {
  const observer = new IntersectionObserver(entries => {
    for (const {target, isIntersecting} of entries) {
      if (!isIntersecting) continue;
      observer.unobserve(target);
      if (target.hasAttribute('data-reveal')) {
        tween(300, 1000, p => {
          target.style.opacity = p;
          target.style.transform = `translateY(${50*(1-expoOut(p))}px)`;
        });
      } else {
        tween(400, 1000, p => {
          target.style.width = `${50*quadInOut(p)}px`;
        });
      }
    }
  }, {root: null, rootMargin: '0px', threshold: 0});

  document.querySelectorAll('[data-reveal]').forEach(el => {
    el.style.opacity = '0';
    el.style.transform = 'translateY(50px)';
    observer.observe(el);
  });
  document.querySelectorAll('[data-title-line]').forEach(el => {
    el.style.width = '0px';
    observer.observe(el);
  });
}
// With reduced motion, leave content visible in its normal layout.

For a framework, initialize through its lifecycle and disconnect the observer/cancel animation frames on teardown. For production, arrange progressive enhancement so a failed initialization cannot strand text at opacity 0; ensure images have dimensions so loading does not move trigger positions.

If you really want three distinct luxury beats

That would be a new design rather than the exact inspected implementation. Give the label, scissors, and text separate motion wrappers. Trigger them from one section observer, with explicit relative starts—for example label 0ms, scissors 120ms, headline 240ms—and use smaller rise distances on the smaller elements. A shared trigger gives reproducible choreography; independent element observers make the sequence depend on scroll speed and layout. Keep paragraph/button grouped with the headline unless there is a reason to delay reading or action.

Improvements supported by this audit

  • Use one reveal wrapper for the service grid. Remove the duplicate parent/child fade unless compounded opacity and up to 100px initial movement are intentional.
  • Give cards a consistent idle state. Replace the mismatch between 249px first-load and 70px after-hover offsets. Keep a title visible before interaction.
  • Keep card content usable on touch and keyboard. Show essential information by default; support focus-visible/focus-within when hover reveals extra detail. The inspected IX2 card events are pointer over/out, not focus events.
  • Use transform-based decorative growth where practical. scaleX/scaleY avoid repeated width/height layout updates. Preserve transform-origin to keep the same growing direction. If you want the Upscale label to move, animate it explicitly or intentionally retain layout growth.
  • Handle reduced motion explicitly. The inspected body lacks data-wf-ix-vacation. This bundle’s IX2 reduced-motion guard requires that attribute plus the media preference, so presence of reduced-motion code in the runtime alone does not prove the page enables it. The shared CSS has no dedicated reduced-motion rule. Prefer visible content, no large translations, and immediate panel states when requested.
  • Remove obsolete definitions. Empty target actions, duplicate frame markup, and absent-component animation lists obscure what actually runs.
  • Choose ornament speed deliberately. The original takes 2.5 seconds to finish. Keeping the overlap but shortening its delays/durations can improve responsiveness; there is no universal faster-is-better rule.
